# VQA pointer contracts

`VQAPointersTest` compiles the production default and engine memory-handler bodies and the production cached stream handler. It checks allocation, lock, unlock and free through the public `VQA_POINTER_H_FUNC` signature, including pointer tokens with the high bits set, and checks absolute and relative cached reads against a logical file offset. Run `ctest --test-dir build -C Debug -R '^vqapointers$' --output-on-failure` after building `VQAPointersTest`; repeat with Release for optimized checks.

The VQA memory and event handlers return `std::intptr_t` because allocation and image-lock events return addresses. Stream and audio handlers keep their 32-bit status and byte-count contracts. `VQALoopCache::FileOffset` is a 32-bit file position, while `Ptr` is the native cache allocation pointer. VQA audio completion takes a real `void *` buffer argument matching the audio callback declaration. These changes preserve Win32 behavior and prevent pointer truncation on x64; callback implementers must use the updated memory/event return type. The tests do not launch a movie or establish audio playback.

The test also compiles the production `VQA_OpenAudio` caller and the early acceptance guard of `Open_Audio_Handler`, ending before DirectSound initialization. The real `AhandleInitParams` contains two callback pointers and grows from 16 to 24 bytes on x64. Tests verify that the native caller's size passes, malformed/legacy sizes and null parameters fail, and a full handle table or unavailable audio is rejected. No audio device is opened by this substitute.
