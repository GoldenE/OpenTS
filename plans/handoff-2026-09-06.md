## Completed 64-bit milestone

## Design contracts already traced

### Logical geometry and physical samples

Keep `ScreenWidth`/`ScreenHeight`, surface width/height/rectangles, map cells, object footprints, input hit tests, and simulation coordinates logical. Physical framebuffer dimensions are logical dimensions multiplied by render density. Merely enlarging the final backend texture or overlaying HD sprites after composition does not implement the plan: it loses ordering, selective depth, shadows, and genuine source detail.

The draft context API declares `RenderDomain {World, UI, Source, Preview}`, `RenderMode {Classic, HD}`, settings outside Options, `Render_Raster_Scale`, `RasterSurfaceView`, `Render_Draw_Point`, `Project_Render_Coord(Coord const&, int density)`, `ScopedWorldOrigin`, and `ScopedScreenSpace`. `Surface::Lock` remains raw physical addressing; `Lock_Raster` is an explicit alias, not a logical-to-physical adapter. Existing raw writers must therefore be audited and adapted. `Render_Rect_To_Raster` does not inherit object-origin residuals; draw points do. Default Source/Preview surfaces are density 1 unless explicitly classified otherwise.

`ScopedWorldOrigin(Coord const& world, Point2D const& legacy_absolute_anchor)` is intended to retain the difference between direct physical projection and scaled legacy projection, with nested scopes restoring their parent. XY scale must multiply before division by `CELL_LEPTON` (256). The legacy Z projection includes a double-precision trigonometric factor, a height-dependent one-pixel correction, and rounding; preserve density-1 behavior and define higher-density rounding deliberately.

World alpha/depth rings need physical XY storage and explicit physical address accessors, while numerical depth and `ScrollOffset` depth bias stay in logical units. Existing density-1 terrain and packed voxel paths remain the Classic reference. Input already maps window coordinates into logical `VideoScaleInfo.GameWidth/Height`; keep that contract and avoid dividing logical coordinates by density a second time. Update the plan's generic inverse-scaling wording accordingly.

### Asset resolution and semantic data

Resolve the final theater-adjusted name and the existing caller's winning source before choosing HD. `CCFileClass::Open` is loose-first; `CDFileClass::Set_Name` considers current/configured directories; common SHP `MixFileClass::Retrieve` calls are cached-MIX-only. Applying one universal loose-first resolver changes Classic behavior. Cached MIX offsets are member-relative while uncached offsets can be physical file offsets; normalize before identity or sidecar reads. Archive cache/free/destruction, theater changes, and owned-image replacement need correct invalidation.

Keep original `ShapeSet` frame counts/dimensions as semantic state. They affect animation, building timing/bounds, and even scorch/crater logic. An HD variant must never replace those fields with physical dimensions. The draft asset header defines RGBA color, remap/shadow/depth channels, logical canvases, frame/facing/direction metadata, sequence temporal multipliers/reverse blocks, source identity/generation/digest, and pinned cache APIs. The actual source adapters and malformed-input/resource-limit handling need review and tests; declarations alone are not proof of safe behavior.

### Animation and world-origin integration

`StageClass` is header-only. Its countdown's programmed `DelayTime`, not the current `Rate`, owns an active interval: rate changes can leave that countdown untouched. The new accessors add no fields. `Sample_Render_Stage` currently computes a clamped 0–65536 progress from `(elapsed - 1) * 256 + intra_tick`, divided by the programmed interval in the same units. The minus one reflects `Frame++` after completed logic. It accepts only step +1/-1; held/unsupported stages return no direction. This draft requires production-owner timing tests before acceptance.

The draw selector must never predict the next logical frame. At an interval boundary it holds the terminal subframe until simulation advances. Reverse and ping-pong playback require direction-specific artwork blocks. Test reverse steps, loop edges, ping-pong flips, building start/count windows, infantry sequence changes, active-interval rate changes, held stages, and nested scope restoration for continuity, not merely in-range indices. Smooth-motion-disabled intra-tick input should be zero; do not blindly use a helper whose disabled result is 256.

Pending origin scopes belong around `ObjectClass::Render`, Tactical pre/body/post object hooks, building overlays and direct factory-door vehicle draws, with separate scopes for nested animation draws. Body rendering and hook anchors can differ (`Render_Coord` versus `Center_Coord`); retain the right owner and render offset. Ground shadows/line endpoints must not accidentally inherit a body's residual, and UI/preview draws need screen-space scopes. The asset selector `Select_Animated_Frame(variant, logical, direction, fraction65536, rawFacing256)` can consume the draft `Current_Render_Animation` context once the consumers and draw helper are implemented.

Voxel facing improvements require one bucket count for both actual transform quantization and all body/shadow/turret/barrel/frame/ramp cache keys. More keys pointing at the same old 32 transforms do not improve rotation. Bound cache growth. Optional denser VXL/HVA data must normalize model size, bounds, pivots, transforms and attachments rather than enlarging the game object.
